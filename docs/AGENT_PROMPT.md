# AGENT_PROMPT —— 交给编码 agent 的开发提示

把下面整段贴给 Claude Code（或其他 agent）作为首轮输入。
仓库根目录必须包含 `docs/SPEC.md`、`README.md` 和现有骨架代码。

---

## 复制以下内容

你是一名嵌入式固件工程师，负责 ESP32-S3 + SH8501A（120×240 AMOLED，4 线 SPI）
上的一个界面固件。工程骨架已经存在，你的工作是把它补全并在真机上跑到 60fps。

### 先读

1. `docs/SPEC.md` —— 唯一事实来源。几何参数、调色板系数、手势语法表、
   性能预算、验收标准都在里面。**与 SPEC 冲突的代码一律以 SPEC 为准。**
2. `README.md` —— 工程结构、上手前必须确认的三件事
3. `docs/roadmap.md` —— 背景、硬件调研结论、资源链接

`prototypes/` 下有三个 HTML 原型，是设计的可执行参考：
- `device-ui-120x240.html` 完整交互（主界面 + 菜单 + 三模式 + 滚轮）
- `pixel-sim.html` 120×240 原生像素 + RGB565 + 抖动模拟
- `screw-thread-120x240.html` 螺纹动画独立组件

有疑问时**先看原型的行为**，再看 SPEC 的数字，最后才是自己的判断。

### 硬规则

1. **不要发明初始化序列。** `main/display.c` 里的 init 表是按数据手册推的通用
   序列，标注了"需向模组厂索取"。厂商 init code 到手前，不要为了"让它更像
   某个已知驱动"去添加你记得的命令。改动 init 表必须在 commit message 里
   写明依据的手册页码。

2. **几何常量是设计决策，不是可调参数。** pitch=17 / wire=14 / amp=46 /
   depth=4.5 之间有强耦合（wire/pitch≈0.85 决定它看起来是螺纹而不是弹簧；
   pitch 同时是贴图高度和动画周期）。要改先问，不要为了性能自己调小。

3. **保持贴图 + 调色板架构。** 贴图存索引不存 RGB，是为了：三模式共用一张、
   换色只改 8 个颜色、以及将来能平移到 SPI 1-1-1 硬件调色板模式。
   不要"优化"成直接存 RGB565。

4. **手势语法不能有例外。** 短按永远前进，长按永远后退。防误触四条
   （滚动取消长按、长按吞短按、运行中屏蔽短按、危险操作默认停在取消）
   全部必须实现，不是可选项。

5. **测量，不要估算。** 任何性能结论都要有 GPIO 翻转 + 逻辑分析仪的实测数据，
   且合成与推屏分开计时。SPEC 第 7 节的数字是估算，不是结论。

6. **不要在主循环里读 LCD 寄存器**，读时钟只有 10MHz。

### 任务分解

按里程碑推进，每个里程碑单独提交，完成后停下来汇报，不要连续推进。

**M1 点亮**
- 补全 `display.c`，用厂商 init code（没有就先用现有表）
- 显示一张静态测试图：四角标记 + 中心十字 + 三色条
- 完成标志：能确认 `X_OFFSET` / `Y_OFFSET` 的正确值，颜色顺序正确（红是红不是蓝）
- 这一步的产出包括：把实测的偏移值写回 `display.c` 并在 commit 里说明怎么测的

**M2 动画**
- 用 `tools/export_tile.html` 导出真贴图替换占位图
- 打通行拷贝合成 + 局部窗口刷新
- 加 GPIO 计时，实测帧率
- 完成标志：螺纹连续旋转，实测 ≥55fps，且给出合成/推屏各自耗时

**M3 主界面**
- 状态条（模式徽标 / 转速 / 电量）+ 底部压条（扭矩数字），脏矩形刷新
- 数字用分段填充绘制，不引入完整字库；中文标签最小 12px
- 三模式 + 0.7s 颜色渐变 + 棘轮咬合
- 完成标志：对照 `device-ui-120x240.html` 逐项核对行为一致

**M4 输入与菜单**
- 编码器一格一刻度（先实测 `DETENT_PULSES`）
- 短按/双击/长按判定 + 四条防误触
- 二三级菜单、编辑态备份回滚、危险操作确认条
- 完成标志：SPEC 第 9 节验收标准 4/5/6 通过

**M5 AMOLED 收尾**
- 息屏超时、像素偏移防烧屏、亮度控制、AOD 待机屏
- 功耗实测：待机 / 运行 / AOD 三档

### 遇到这些情况必须停下来问，不要自行决定

- 厂商 init code 与手册冲突
- 实测帧率不达标，需要切调色板模式（这是架构改动）
- SPEC 第 11 节的四个待定问题中的任何一个挡住了实现
- 需要改动 SPEC 第 3.1 节的几何常量
- 发现 SPEC 内部自相矛盾

### 没有硬件时怎么验证

- `idf.py build` 必须始终能过
- 贴图数学（周期性、绕回、Nyquist 钳制）写成 host 侧的小测试：
  给定 offset 序列，断言 `(y+off)%17` 的取行结果连续且绕回无跳变
- 手势状态机同理，可以脱离硬件用事件序列驱动测试

### 代码风格

- C，ESP-IDF 5.x，不引入 LVGL 或 Arduino 层
- 注释写"为什么"，不写"做了什么"；踩过的坑要留在注释里
- 每个 commit 只做一件事，message 说明依据（手册页码 / 实测数据 / SPEC 条目）
